# 구현 계획서: 전출(퇴실) 정산 — 임차인 작성 → 임대인 확인 → 채팅으로 계좌·송금·확인

작성: 2026-11-16 · 상태: 계획(코드 미변경)

## 1. 목표 흐름

임차인이 전출 정산을 **먼저 작성**하고, 임대인이 확인·공제를 확정하면, **계좌번호 수집 → 송금 → 수취 확인**을 앱 채팅 안에서 끝낸다. 전출 직전에 **연말정산 자료를 미리 내려받도록** 안내한다.

```
임차인: 퇴실 신청(희망일·시설 상태 작성)
  └ 안내: "퇴실 후엔 로그인이 끊깁니다. 연말정산 납부확인서를 지금 내려받으세요" [내려받기]
임대인: 신청 확인 → 현장 점검 → 정산서 작성(미납·공과금·청소비·파손) → 임차인에게 전달(채팅 카드)
임차인: 정산서 검토 → 동의·서명 + 계좌번호 입력(채팅 카드)
임대인: 계좌 확인 → 송금 → "송금했습니다" 처리(이체 증빙 메모)
임차인: "받았습니다" 확인(채팅 카드)  → 정산 완료
시스템: 로그인 수단 정리(바로가기·기기·링크) + 읽기 전용 기간 시작
```

## 2. 현재 구조와 차이

| 항목 | 지금 | 바뀔 것 |
|---|---|---|
| 시작 | 임대인이 `POST /checkout/calculate`로 바로 계산 | 임차인 **퇴실 신청** 단계 추가(상태 `REQUESTED`) |
| 작성 | 임대인 입력 값으로 계산(`CheckOutSettlement.calculate_for_room`) | 임차인이 희망일·시설 상태를 쓰고, 임대인이 점검·공제를 채움 |
| 계좌 | `tenant_agree`에서 계좌+서명 한 번에 | 정산서 확정 **뒤** 계좌 수집, 본인 명의 확인 문구 |
| 송금 확인 | 임대인이 "완료" 누르면 끝(`complete_refund_and_vacate`) | **송금 → 임차인 수취 확인** 2단계, 이의 제기 가능 |
| 완료 시 | (Gemini 구현) `reset_activation`으로 전체 삭제 | 아래 5절: 연말정산 접근 보존 |
| 채팅 | 시작 시 자동 안내 1건 | 단계마다 **카드형 채팅**(버튼이 있는 `DirectChat`) |

## 3. 상태 전이 (`CheckOutSettlement.status`)

`REQUESTED`(임차인 신청) → `CALCULATED`(임대인 정산서 전달) → `AGREED`(임차인 동의+계좌) → `PAID`(임대인 송금 표시) → `COMPLETED`(임차인 수취 확인 또는 자동 확정)
- `DISPUTED`: 임차인 이의(계산 이의 또는 미수취). 임대인이 수정해 `CALCULATED`로 되돌리거나 증빙으로 해결.
- 기존 값(`CALCULATED/AGREED/COMPLETED`)과 호환: 기존 데이터는 그대로 읽힌다. `PAID`·`REQUESTED`·`DISPUTED`만 새로 생긴다.
- 보증금 반환 시한(통상 퇴실일 기준) 경과 시 임대인에게 알림.

## 4. 채팅 카드 설계

`DirectChat`에는 이미 `quick_action_label/url`이 있다. 이를 확장해 **카드 종류(`card`)와 액션 목록**을 둔다.

| 단계 | 보내는 쪽 | 카드 내용 | 버튼 |
|---|---|---|---|
| 신청 | 임차인 | 퇴실 희망일·메모 | (임대인) 점검 일정 정하기 |
| 정산서 전달 | 임대인 | 보증금 − 공제 내역 표, 반환 예정액 | (임차인) 동의하고 계좌 입력 / 이의 제기 |
| 계좌 접수 | 임차인 | 은행·계좌 **끝 4자리만 표시**, 예금주 | (임대인) 계좌 확인 |
| 송금 | 임대인 | 송금액·일시·이체 메모 | (임차인) 받았습니다 / 못 받았습니다 |
| 완료 | 시스템 | 정산 완료, 영수 요약 | 연말정산 납부확인서 내려받기 |

- 계좌 전체 번호는 채팅 본문에 **남기지 않는다**. 정산서(`refund_bank_account`)에만 저장하고, 채팅엔 마스킹한다. 임대인 화면에서만 전체를 보인다.
- 카드 상태(처리됨/대기)는 정산서 상태에서 파생해 중복 클릭을 막는다.
- 임차인 앱이 간편 비밀번호(PIN) 접속이면 **계좌 입력·동의·수취 확인은 막는다**(법적·금전 행위, 정식 비밀번호 로그인 필요). 기존 `pin_guard` 허용 목록으로 처리.

## 5. 연말정산 자료 사전 안내 (Gemini 구현과 충돌 지점)

- **문제**: Gemini 구현은 퇴실 완료 즉시 `reset_activation`을 호출한다. 이 함수는 비밀번호를 초기값으로 되돌려 사실상 로그인을 끊고, 개인정보 동의·본인확인 기록도 지운다. 퇴실 직후 납부확인서·정산 영수를 못 받는다.
- **계획**:
  1. 퇴실 신청 시점과 정산서 전달 시점에 **"연말정산 납부확인서 미리 내려받기"** 카드를 띄운다(올해 납부분 기준, 해가 바뀌면 다시 발급 가능하다고 안내).
  2. 퇴실 완료 시 삭제 대상은 **바로가기·간편 비밀번호·등록 기기·미사용 링크·연결 요청**으로 한정하고, 비밀번호는 유지한 채 **읽기 전용 기간(예: 퇴실 후 90일)** 을 둔다. 이 기간엔 납부확인서·정산서 조회·내려받기만 가능, 납부·계약·채팅 쓰기는 막는다.
  3. 기간이 지나면 비밀번호를 무효화한다(`password` 폐기). 개인정보 보관 기한 정책과 맞춘다.
  4. 개인정보 동의·본인확인 기록은 **지우지 않는다**(분쟁 증빙). `reset_activation` 재사용 대신 `purge_login_methods(tenant)`를 새로 만든다.
- 퇴실한 사람이 다시 입주하면 그때 새 링크로 재등록한다(기존 `invite` 흐름 그대로).

## 6. 보안·부정 방지

- 계좌는 **임차인 본인 명의**여야 함을 안내하고, 예금주명 입력을 받아 임차인 이름과 다르면 임대인에게 경고(자동 차단은 하지 않음 — 배우자·가족 계좌 가능).
- 계좌 **변경은 정산 확정 전까지만**, 확정 후 변경 요청은 임대인 확인 + 임차인 재동의. (송금 직전 계좌 바꿔치기 방지)
- 모든 단계 이벤트를 `PoolObj.save(action=...)`로 남겨 시각·주체를 증빙으로 쓴다.
- 임대인이 `PAID`로 표시해도 **임차인 확인이 없으면 `COMPLETED`로 넘기지 않는다**(자동 확정은 N일 후, 이의 없을 때만, 사전 안내 필수).
- 앱은 **실제 송금을 하지 않는다**(은행 이체는 임대인이 은행 앱에서). 앱은 안내·기록·확인만 한다. 은행 문자 자동 대조(기존 SMS 입금 파서 방향)는 후속 과제.

## 7. 구현 단계와 시험

1. **모델·상태**: `REQUESTED/PAID/DISPUTED` 추가, `tenant_request_checkout`, `mark_paid`, `tenant_confirm_received`, 이의 처리. 기존 3상태 시험 회귀 확인.
2. **API**: 임차인 `POST /checkout/request`, `/checkout/{id}/agree`(기존), `/checkout/{id}/confirm-received`, `/checkout/{id}/dispute`; 임대인 `/checkout/{id}/calculate-from-request`, `/checkout/{id}/mark-paid`.
3. **채팅 카드**: `DirectChat.card`·`actions` 필드, 임차인·임대인 채팅 화면의 카드 렌더링(버튼 → 위 API).
4. **연말정산 안내·읽기 전용 기간**: 카드, `purge_login_methods`, 로그인·쓰기 가드에 "퇴실 후 조회 전용" 반영.
5. **시험**(`tests/test_rent3_pool_suite.py`에 이어서): 상태 전이 전체, 계좌 마스킹, PIN 접속 차단, 읽기 전용 기간 조회 가능/쓰기 불가, 이의 제기 경로, 남의 호실 접근 403, 폰 크기 실화면 시험 1개.

## 8. 먼저 정해야 할 것

1. 퇴실 후 **읽기 전용 기간**: 90일? 연말정산 기간(다음 해 2월 말)까지?
2. 임차인 **수취 확인 자동 확정** 기간(예: 7일)과 이의 처리 책임자.
3. 정산서 작성 주체: 임차인은 신청·시설 상태만, 금액은 임대인 확정(제안) vs 임차인도 항목별 입력.
4. 예금주명이 임차인과 다른 계좌를 허용할지(제안: 허용하되 임대인에게 경고).
