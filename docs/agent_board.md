#### 질문 3건 검토 답변
1. **PIN 허용 목록(`authz.PIN_WRITE_ALLOW`) 점검**:
   - 일상 업무(`/messages`, `/pay`, `/vehicle`, `/checkin`, `/tickets`, `/billing-notices/.../acknowledge`, `/support/messages`, `/auth/logout`) 구성은 적절합니다.
   - **보완 권고(작은 틈 2가지)**:
     - `/myhome/.../balance-registry-check`와 `/myhome/.../insurance-proof`는 출입 정보(도어락) 교부와 직접 연결된 1회성 법적·안전 확인이므로 일반 아이디·비밀번호 로그인 시에만 하도록 목록에서 빼는 편이 더 안전합니다.
     - `/rent3_contract/sessions/.../messages`는 `proposal`(제안)·`change_request`(수정 요청)까지 함께 열리므로, 계약 관련 쓰기를 일관되게 막으려면 목록에서 제외하거나(재계약·계약방 글쓰기도 일반 로그인) `question`만 허용하는 것이 안전합니다.
2. **관리인 입장 유효 시간 120분(`authz.GRANT_MINUTES`)**:
   - 사용자가 원격 지원 허용을 끄면 즉시 닫히는 장치가 있어 120분도 큰 위험은 없지만, 실제 1회 지원 응대 기준으로 **60분(1시간)** 정도로 줄여 두는 것을 권장합니다(모자라면 관리인이 다시 입장하면 됩니다).
3. **임대인용 간편 비밀번호(PIN) 도입 시기**:
   - **임차인 실사용 검증 뒤**가 맞습니다. 실제 도메인 HTTPS·iOS Safari 홈 화면 추가·안드로이드 PWA 동작을 임차인 쪽에서 먼저 확인하고, 이후 임대인용 `PIN_WRITE_ALLOW`(수납/정산/세무 제외, 조회·단순 메모/메시지 위주)를 설계해 여는 순서로 갑니다.
