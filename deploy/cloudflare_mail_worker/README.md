# 입금 메일 자동 정리 — Cloudflare 연결 순서서

은행 입금 알림 메일 → (임대인 메일의 자동 전달) → `pay-<토큰>@in.<내도메인>` → **Cloudflare Email Routing** → **이 Worker** → Rent3 서버 웹훅(`/api/rent3/inbound/mail`) → 확인 대기 / 자동 수납 → 임대인 알림.

Cloudflare 쪽 설정은 **한 번만** 합니다. 임대인이 늘어도 Cloudflare에서 할 일은 없습니다(주소의 토큰은 서버가 발급).

> ⚠️ 이 문서의 Cloudflare 화면 이름은 시간이 지나면 달라질 수 있습니다. 막히면 화면 문구를 알려 주세요.
> ⚠️ 서비스 주소가 `*.sslip.io` 인 동안에는 **수신 도메인으로 쓸 수 없습니다**(DNS를 설정할 수 없음). 새 도메인이 필요합니다. 웹훅 주소(`WEBHOOK_URL`)는 지금 주소 그대로 써도 됩니다.

## 준비물
- Cloudflare 계정, 도메인 1개(Cloudflare Registrar에서 등록하면 DNS가 바로 연결됨 — 도메인 비용 발생)
- Node.js 18 이상(PC), 이 폴더(`deploy/cloudflare_mail_worker`)
- Coolify에서 서비스 환경변수를 바꿀 수 있는 권한

## 1. 도메인 수신 켜기
1. Cloudflare 대시보드 → 도메인 선택 → **이메일 → Email Routing** → 사용 설정. 필요한 MX·SPF 레코드를 Cloudflare가 자동으로 추가합니다.
2. 수신 주소로 `in.<내도메인>` 같은 하위 도메인을 쓰려면 Email Routing 설정에서 하위 도메인을 추가합니다(도메인 전체를 수신용으로 써도 됩니다. 가장 단순함).
3. 수신 도메인 값을 적어 둡니다 → 아래 `RENT3_MAIL_DOMAIN`.

## 2. Worker 배포
```
cd deploy/cloudflare_mail_worker
npm install
npx wrangler login
npx wrangler secret put RENT3_MAIL_SECRET      # 길고 무작위인 문자열(예: 40자 이상). 같은 값을 Coolify에도 넣는다. 저장소·메신저에 남기지 말 것
npx wrangler deploy
```
- `wrangler.toml` 의 `WEBHOOK_URL` 이 서비스 주소와 맞는지 확인합니다.
- `DEBUG_HEADERS = "1"` 인 동안 `npx wrangler tail` 로 로그를 볼 수 있습니다(헤더 이름과 인증 결과 한 줄만 나오고, 본문·주소는 나오지 않음).

## 3. 수신 규칙 연결
Email Routing → **라우팅 규칙 → Catch-all 주소** → 작업 **Worker로 보내기** → `rent3-mail-worker` 선택 → 저장·사용.
(주소가 `pay-<토큰>@…` 이므로 모든 주소를 한 Worker가 받습니다.)

## 4. 서버(Coolify) 환경변수
| 이름 | 값 | 설명 |
|---|---|---|
| `RENT3_MAIL_SECRET` | Worker secret 과 **같은 값** | 웹훅 서명 비밀키. 없으면 서버가 수신을 거부(503) |
| `RENT3_MAIL_DOMAIN` | `in.<내도메인>` | 임대인에게 보여 줄 수신 주소의 도메인 |
| `RENT3_MAIL_EXTRA_DOMAINS` | `gmail.com` | **테스트 때만.** 일반 메일로 시험할 때 허용할 발신 도메인 |
| `RENT3_MAIL_TEST_BRANCHES` | `main` | **테스트 때만.** 위 도메인이 적용될 지점(쉼표로 여러 개) |

변경 후 서비스를 재배포합니다.

## 5. 내가 내게 메일을 보내 확인하기 (테스트)
1. 임대인 앱 → ☰ → **📧 입금 메일 자동 정리 (선택)** → 동의, 은행 `NH농협은행`, 입금 계좌 끝 4자리 입력 → **켜기**. (테스트 지점이면 위쪽에 🧪 테스트 모드 띠가 보입니다.)
2. 화면의 **전용 수신 주소**를 복사합니다.
3. 내 지메일에서 그 주소로 아래 본문(농협 가정 형식)을 보냅니다. 입금자·호실·금액은 **실제 계약**(예: 201호 임차인 이름, 월 청구액)에 맞춰야 합니다. 날짜는 오늘.
```
NH농협은행 전자금융 입금 안내
거래일시 : 2026/11/20 10:23:45
거래구분 : 입금
입금계좌 : 351-****-4567-83
보낸분 : 이민수
입금금액 : 550,000원
거래후잔액 : 1,230,000원
메모 : 201호 11월 월세
```
   (입금 계좌 끝 4자리를 `6783`으로 설정한 경우의 예입니다. 숫자만 이어 붙인 마지막 4자리가 서버가 비교하는 값입니다.)
4. 잠시 뒤 앱의 🔔에 **확인 대기 입금 메일 1건**이 뜨면 📧 화면에서 **✅ 처리** → 수납 현황에 반영되는지 확인합니다.
5. 테스트 도메인 메일은 **항상 확인 대기**이며 자동 수납되지 않습니다(의도된 동작).

## 6. 지메일 자동 전달 확인 코드
임대인이 지메일에서 전용 주소로 **자동 전달**을 등록하면 구글이 그 주소로 확인 메일을 보냅니다. 서버가 숫자 코드만 읽어 📧 화면에 **1시간 동안** 보여 줍니다(링크는 저장·표시하지 않음). 지메일의 전달 설정 화면에 코드를 입력한 뒤 **입력했어요**를 누르면 지워집니다. 코드를 읽지 못하면 오류 안내가 뜹니다.

## 7. 첫 실제 메일로 인증 헤더 확정 (중요)
- 서버는 Worker가 보내는 `dkim_pass_domains` 가 은행 도메인일 때만 "발신 확인됨"으로 봅니다. 값이 비어 있으면 모두 **확인 대기(발신 확인 불가)** 로 떨어지므로 오수납은 없지만 자동 수납도 안 됩니다.
- Cloudflare 가 `Authentication-Results` 를 실제로 어떤 형식으로 붙이는지는 **첫 메일의 `wrangler tail` 로그**로 확인해야 합니다. 로그의 `auth-results:` 줄(도메인 이름 외 개인정보는 가려서)을 알려 주세요. 확인되면 `wrangler.toml` 의 `AUTHSERV_ID` 를 채우고 `DEBUG_HEADERS` 를 `"0"` 으로 바꿔 다시 배포합니다.
- 농협 해석기는 **가정 형식**입니다. 실제 농협 입금 메일을 받으면 형식을 비교해 해석기를 보정하고, 그 뒤에야 "일치하면 자동 처리"가 열립니다.

## 8. 운영으로 전환
- `RENT3_MAIL_EXTRA_DOMAINS` · `RENT3_MAIL_TEST_BRANCHES` 를 **삭제**하고 재배포.
- `DEBUG_HEADERS = "0"`.
- 개인정보처리방침·약관에 입금 메일 처리(수집 항목·보관 90일·철회) 문구를 반영(법무 검토).

## 문제 해결
| 증상 | 확인 |
|---|---|
| 서버가 503 | `RENT3_MAIL_SECRET` 이 Coolify에 없음 |
| 서버가 401 | Worker secret 과 Coolify 값이 다름 / PC·서버 시각 차이 10분 초과 |
| 로그에 webhook 200, 앱에 아무것도 없음 | 토큰이 다른 주소로 보냄, 임대인이 꺼져 있음, 상태 `REJECTED`(응답에 `status` 가 찍힘) |
| 처리 내역에 "허용된 은행 발신이 아닙니다" | 테스트 환경변수 두 개 확인(`RENT3_MAIL_TEST_BRANCHES` 에 지점 포함) |
| "메일 형식을 읽지 못했습니다" | 본문이 가정 형식과 다름(거래구분·입금계좌·입금금액·거래일시 줄 필요) |
| "내 입금 계좌가 아닙니다" | 설정한 끝 4자리와 메일의 계좌 끝 4자리 불일치 |
