# 공동 계약 시험 PLAYBOOK — 임대인(Claude) × 임차인(Gemini)

두 AI가 **같은 폴더와 같은 시험 서버**를 쓰면서, 한 명은 임대인 · 한 명은 임차인 역할로 번갈아 공동 계약을 끝까지 진행합니다.
서로 대화하지 않습니다. **진행 상태 파일(`e2e_runtime/state.json`)** 이 "지금 누구 차례인가"를 알려 주고, 정해진 명령만 실행합니다.

## 0. 준비 (사람이 한 번만)

1. 터미널을 하나 열어 시험 서버를 켭니다. 켜 둔 채로 둡니다.
   ```
   py scripts/e2e_pair/server.py --fresh
   ```
   - 이 PC 안(127.0.0.1:9070)에서만 열리는 **시험 전용 서버**입니다. 운영 서버가 아닙니다.
   - 시연용 로그인(`1212`)과 가짜 본인인증(인증번호 `000000`)이 허용됩니다. 시험 데이터는 `e2e_runtime/pool/` 에만 쌓이고 운영 데이터와 분리됩니다.
2. 진행 상태를 비웁니다.
   ```
   py scripts/e2e_pair/play.py reset
   ```
3. 각 AI 창에 역할을 알려 줍니다.
   - Claude 창: `scripts/e2e_pair/PLAYBOOK.md 를 읽고 임대인(lessor) 역할을 시작해.`
   - Gemini 창: `scripts/e2e_pair/PLAYBOOK.md 를 읽고 임차인(tenant) 역할을 시작해.`

## 1. 규칙 (두 AI 모두)

- **내 역할의 명령만** 실행합니다. 임대인은 `play.py lessor ...`, 임차인은 `play.py tenant ...`.
- **API를 직접 호출하지 않습니다.** 주소나 요청 형식을 추측해서 `curl`/`requests` 로 호출하지 마세요. 최근 많이 바뀌었고, 잘못된 요청은 시험 데이터를 어지럽힙니다. 아래 명령이 모든 호출을 대신합니다.
- **`e2e_runtime/state.json` 을 직접 고치지 않습니다.** 명령이 알아서 갱신합니다.
- **내 차례일 때만** 실행합니다. 차례가 아니면 도구가 `[거부]` 하고 누구 차례인지 알려 줍니다. 그러면 기다렸다가 다시 확인하세요.
- 서버 코드·테스트 코드·데이터를 시험 중에 수정하지 않습니다. 문제를 발견하면 고치지 말고 **보고만** 합니다(아래 5).
- 시험용 비밀번호 외의 실제 계정 정보·키를 이 폴더나 대화에 쓰지 않습니다.

## 2. 순서 (19단계, 번갈아)

현재 상태는 언제든 `py scripts/e2e_pair/play.py status` 로 확인합니다.

| # | 역할 | 명령 | 하는 일 |
|---|---|---|---|
| 1 | 임대인 | `play.py lessor prepare` | 로그인, 시험 호실 만들어 공개 |
| 2 | **임차인** | `play.py tenant signup` | 가입 + 시험용 본인인증 + 로그인 확인 |
| 3 | 임대인 | `play.py lessor call` | 계약 호출 + 입주일·특약 사전 작성 |
| 4 | **임차인** | `play.py tenant respond` | 이메일 사전 작성 + 호출 응답 |
| 5 | 임대인 | `play.py lessor step1` | ① 등기부 제시 + 신분증 확인 |
| 6 | **임차인** | `play.py tenant step1` | ① 등기부 직접 열람 값 제출 + 신분증 확인 |
| 7 | 임대인 | `play.py lessor photo` | ② 점검 사진 |
| 8 | **임차인** | `play.py tenant photo` | ② 점검 사진 |
| 9 | 임대인 | `play.py lessor step2` | ② 점검 확인 |
| 10 | **임차인** | `play.py tenant step2` | ② 점검 확인(잠금) |
| 11 | 임대인 | `play.py lessor agree` | ③ 조건 합의 |
| 12 | **임차인** | `play.py tenant agree` | ③ 조건 합의 |
| 13 | 임대인 | `play.py lessor sign` | ④ 전자서명 |
| 14 | **임차인** | `play.py tenant sign` | ④ 전자서명 |
| 15 | **임차인** | `play.py tenant recheck` | 체결 직전 등기부 재열람(변동 없음) |
| 16 | 임대인 | `play.py lessor complete` | ⑤ 계약금 입금 확인 + 체결 |
| 17 | **임차인** | `play.py tenant balance_check` | 잔금일 등기부 재열람(변동 없음) |
| 18 | 임대인 | `play.py lessor release_keys` | 잔금 확인 + 도어락 교부 |
| 19 | **임차인** | `play.py tenant verify_keys` | 도어락 공개 + 계약 진위 확인(INTACT) |

모든 명령은 `py scripts/e2e_pair/play.py <역할> <단계>` 형식입니다.

## 3. 내 차례를 기다리는 방법

AI는 알림을 받을 수 없으므로 **상태를 확인하고, 내 차례가 아니면 잠깐 쉬었다가 다시 확인**합니다.

```
py scripts/e2e_pair/play.py status
```

- `다음 차례: [tenant] ...` 가 내 역할이면 그 명령을 그대로 실행합니다.
- 내 차례가 아니면 15~20초 쉬었다가(`Start-Sleep 15`) 다시 `status`. **최대 20번(약 5분)** 기다려도 변화가 없으면 사람에게 알리고 멈춥니다.
- 한 단계를 실행한 뒤에는 출력의 `다음 차례:` 줄을 보고, 상대 차례면 기다립니다.

## 4. 실패했을 때

- `[실패] ...` 가 나오면 **상태는 그대로**입니다. 메시지를 그대로 사람에게 전하고, 같은 명령을 다시 실행해도 되는지 판단합니다.
  - 서버가 꺼져 있다는 메시지(연결할 수 없음): 사람에게 시험 서버를 켜 달라고 요청합니다.
  - 그 밖의 실패: **서버를 고치려 하지 말고** 실패한 단계, 메시지, 직전 단계를 보고합니다. (실제 결함일 수 있습니다.)
- `[거부]` 는 차례가 아니라는 뜻입니다. 실패가 아닙니다.

## 5. 보고 형식 (시험이 끝나거나 멈췄을 때)

```
결과: 성공 N/19단계 (또는 N단계에서 중단)
실패 단계: <역할> <단계> — <메시지 그대로>
이상한 점: <화면 문구, 숫자, 순서 등 기대와 달랐던 것>
```

## 6. 보안 공격 시험 (한 사람이 실행, 정상 시험이 끝난 뒤)

정상 흐름만으로는 보안 장치가 실제로 막는지 알 수 없습니다. 아래는 일부러 잘못된 요청을 보내 서버가 막는지 확인합니다.

```
py scripts/e2e_pair/play.py attack
```

- 21개 항목이 모두 `✅ 막힘` 이어야 합니다(본인인증 없이 계약 시작, 남의 계약 열람, 다른 등기부 값 제출, 재열람 없이 체결, 잔금 확인 전 도어락 교부 등).
- `❌ 뚫림` 이 하나라도 있으면 **심각한 결함**이니 즉시 사람에게 보고합니다.
- 이 명령은 자체적으로 새 호실·새 임차인을 만들어 쓰므로 진행 상태(`state.json`)에 영향을 주지 않습니다.

## 7. 사람 없이 한 번에 확인하고 싶을 때

```
py scripts/e2e_pair/play.py auto
```

두 역할을 한 프로세스가 끝까지 실행합니다(19단계). 두 AI의 번갈아 진행 시험 전에 **전체 흐름이 되는지** 확인하는 용도입니다. 끝나면 상태가 "완료"로 남으므로, 번갈아 시험을 하려면 먼저 `play.py reset` 을 실행하세요.

## 8. 이 시험이 확인하지 못하는 것

- 인터넷등기소 열람과 본인인증은 **시험용 값**입니다(가짜). 실제 위조 서류·실명 확인은 검증하지 못합니다.
- 화면(버튼·문구·모바일 레이아웃)은 보지 않습니다. 이 도구는 서버의 흐름과 보안 규칙만 시험합니다.
- 한 사람이 두 역할을 하므로 상대가 응답하지 않거나 중간에 마음이 바뀌는 상황은 흉내만 낼 수 있습니다.

## 9. 끝난 뒤 정리

- 시험 서버 터미널에서 `Ctrl+C` 로 끕니다.
- `e2e_runtime/` 폴더를 지우면 시험 데이터와 시험용 계정 정보가 모두 사라집니다(git 에는 올라가지 않습니다).
